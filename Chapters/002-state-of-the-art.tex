\section{BitTorrent Protocol}
\label{BitTorrent}

Normalmente, quando se pretende transferir conteúdos multimédia da internet, estes são disponiblizados atravÊs de magnet links, que utilizam HTTP. Desta forma, tudo o custo da operação recaí sobre o servidor que é responsável por distribuir estes conteúdos, que normalmente será o CDN mais próximo do utilizador. Este processo, necessita de bastante largura de banda entre o utilizador e o servidor, o que seria impossível transferir ficheiros inteiros de uma só vez. Para esse efeito, antes da tranferência dos conteúdos, o servidor primeiro começa por dividir os conteúdos em vários pedaços e calcula os seus hashes, de seguida constitue um ficheiro de metadados que vai armazenar esses mesmos hashes, junto com as informações do ficheiro. Desta forma, o cliente transfere primeiro o metafile, tem acesso aos hashs corretos e pede ao servidor cada chunk, verificando-o com o seu respetivo hash no fim para confirmar a sua integridade. No final, quando reúnido todos os hashs, obtêm uma copia do conteúdo original. Contudo, apesar de aproveitar mais a largura de banda disponivel, tudo o custo da operação recaí sobre esse mesmo servidor. Além disso, o servidor é considerado como "Single Source of Truth", o que significa que caso esse não consiga disponiblizar mais esse conteúdo, não existe outra forma do obter.

Por outro lado, pode-se utilizar o BitTorrent um dos protocolos P2P mais utilizados hoje em dia (colocar métricas), este permite transfêrencias teóricamente mais rápidas e distribuidas, tomando partido de uma rede P2P que permite compartilhar os conteúdos multimédia entre os peers dentro do swarm.

Para isto, um ficheiro com os metadados necessários é disponiblizado, \textbf{.torrent}. Este, contém os hashes dos chunks que constituem o conteúdo que vai ser transferido e contém a forma como o client vai interagir com a rede, normalmente contém: os urls do trackers, ou ips dos bootstraps para o DHT, ou a conexão através de PEX. Normalmente, o \textbf{.torrent} é criado pelo \textbf{Seeder} que disponibliza o ficheiro, e é distribuido por outras fontes.

\subsection{Roles in the BitTorrent Swarm}
\begin{itemize}
  \item \textbf{Trackers:} São nodes dedicados centralizados ou semi-centralizados, que não disponiblizam nenhum conteúdo multimédia, limitam-se apenas a disponiblizar listas de ips de nodes no swarm, estes são  importantes para ajudar outros nodes a entrarem no swarm. Normalmente, após os nodes se conectarem, este comunicam diretamente entre si, utilizando o tracker para conhecer novos nodes, que possam conter parte dos chunks que necessitam para completar a transfência do contéudo que pertendem.

  \item \textbf{Downloaders (Leechers):} Estes são nodes que têm menos de 100\% do ficheiro original, o seu trabalho é realizar a transferência dos chunks que lhe faltam para completar a copia do ficheiro, enquanto realizam o carregamento dos chunks que já possuem e que são validados para outros peers. Além disso, podem ser conhecidos também como leechers, contudo este nome pode ser conotado negativamente, visto que podem ser nodes que apenas efetuam o download e não praticam o carregamento para outros nodes, prejudicando a distribuição na rede.

  \item \textbf{Seeders:} Os seeders são nodes que possuem 100\% do ficheiro, portanto apenas pratica o carregamento de chunks para outros nodes e não realiza a transferência de outros nodes. Estes nodes são essenciais, visto que caso não existam mais seeders na rede de um determinado ficheiro, pode-se concluir que é ímpossivel obte-lo por completo, desta forma é necessário existir pelo menos um seeder para efetuar uma transferência.

  \item \textbf{Peers:} Estes são cada um dos nodes que fazem parte do swarm, podem ser Seeders ou Downloaders.
\end{itemize}
