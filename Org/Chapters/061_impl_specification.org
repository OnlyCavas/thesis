** Torrent Specification
:PROPERTIES:
:CUSTOM_ID: impl_torrent_specification
:END:

As depicted in [[#torrent_specification][Section 2.1.1]], the {{{mark(.torrent)}}} format encodes torrent metadata using Bencode. The implementation supports both *V1* and *V2* specifications, covering three operations: *Creation*, generating a {{{mark(.torrent)}}} metadata file from a single file or a directory, *Inspection*, parsing and presenting the torrent's metadata fields (using the {{{mark(serde\_bencode)}}} deserialization framework), and *Validation*, which verifies both structural and piece hash integrity against the metadata rules.

# Figure [display [creation, inspect and verify]]

Beyond the standard specification fields, announce list, web seeds and DHT node fields support three declaration formats: standard IPv4 for ClearNet peers, *.b32.i2p* human readable I2P addresses, and full base 64 I2P destination for direct private connections. Thus, the user relies on {{{mark(.torrent)}}} to provide the details needed to bootstrap a swarm over either ClearNet or I2P without any direct modification.
