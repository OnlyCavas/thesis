** Peer Exchange (PEX)
:PROPERTIES:
:CUSTOM_ID: impl_pex_bep_extension_section
:END:

As specified in Section {{{ref(peer_exchange)}}}, Peer Exchange allows connected peers to share knowledge of other swarm participants without querying the DHT, acting as a low-overhead gossip layer that complements discovery, and enables peer discovery to move faster. In {{{mark(bqti)}}} PEX operates over the same unidirectional control stream as the DHT and BEP handshakes, consistent with the design model established in Section {{{ref(impl_quic_config)}}}.

Once at least one torrent session is active, every {{{mark(60 seconds)}}} the local node broadcasts a PEX message to each known peer of a given connected swarm. Upon the first connection, the full snapshot of up to {{{mark(50)}}} known peers is sent immediately, seeding the counterpart without waiting for the next gossip cycle, in an attempt to sync as many peers as possible from early on. From that point, rather than seeding the full known peer list on every cycle, the current implementation tracks per-peer state, precisely what was last sent to each peer while computing an incremental delta value. For instance, the message only carries peers added since the last exchange and those that have since dropped, keeping message size proportional to churn rather than swarm size, making it as small as possible without compromising function. Each delta is scoped to {{{mark(50)}}} entries across both added and dropped combined, preventing message bloat under high-churn conditions. To maintain a fresh supply of peers, whenever a PEX message arrives, the sender is registered as a known peer and forwarded to Kademlia as an announce. To maintain consistency, dropped peers are evicted from tracking immediately. During a torrent session cycle, it establishes a feedback loop between the PEX and the DHT, where peers discovered through gossip reinforce the distributed index without requiring an explicit lookup. Additionally, all torrent sessions share the same set of known peers, so the process must search for broader peers.

To prevent peer flooding, each swarm tracker is bound to {{{mark(200)}}} peers, preventing unbounded memory growth under large swarms. Beyond that, PEX is fully disabled for private torrents, thereby complying with the protocol specification.
