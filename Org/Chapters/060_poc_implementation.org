The previous chapter established the architecture of the proposed system, a three layer stack composed of QUIC, I2P, and TEE with the objective of achieving a trust-enhanced and privacy-preserving BitTorrent implementation. That said, this chapter details the concrete implementation of {{{mark(bqti)}}}, a working proof-of-concept implemented using Rust.

The following sections detail each component of the stack, starting at the {{{mark(.torrent)}}} file metadata layer through peer discovery protocol extensions, session management, and I2P integration.

** Project Structure
:PROPERTIES:
:CUSTOM_ID: impl_structure
:END:

# (citeme: github project poc link)

The current implementation is organized as a Rust workspace with two crates: the main {{{mark(bqti)}}} crate, containing the full protocol stack. Followed by {{{mark(bqti-ipc)}}} crate, a minimal rust library project defining the shared types for interprocess communication between the daemon and CLI client. By separating both into different projects avoids code replication and reuse in different context.

Moreover, inside the {{{mark(bqti)}}} crate, the remaining code is organized by four top level modules. First, {{{mark(bit\_torrent)}}} module containing the core protocol stack and metadata specification, its responsible for the stock protocol implementation and control. Within, {{{mark(network)}}} crate where QUIC management, {{{mark(dht)}}} Kademlia peer discovery implementation, {{{mark(session)}}} peer wire protocol state machine, and {{{mark(chunks)}}} piece I/O operations, and fine grain. Following this crate, {{{mark(i2p)}}}  module provides the simple SAM client implementation that proxies both {{{mark(bit\_torrent)}}} and {{{mark(network)}}} abstracting the core network management implementation. Finally, {{{mark(ipc)}}} module that is responsible for managing the Unix socket control interface between the daemon and a client, in this case the CLI client.

Also, the implementation is powered by the following open-source Rust crates, acknowledged here in accordance with their responsible licenses:

| {{{mark(ring)}}}    |  Cryptographic primitives               |

| {{{mark(rcgen)}}}    |  X.509 certificate generation               |
