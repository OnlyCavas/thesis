* Implementation
:PROPERTIES:
:CUSTOM_ID: poc_implementation
:END:

The previous chapter established the architecture of the proposed system, a three-layer stack composed of QUIC, I2P, and TEE, to achieve a trust-enhanced, privacy-preserving BitTorrent implementation. This chapter details the concrete implementation of {{{mark(bqti)}}}, a working proof-of-concept implemented using Rust.

The following sections detail each component of the stack, beginning with the {{{mark(.torrent)}}} file metadata layer and extending to peer discovery protocol extensions, session management, and I2P integration.

** Project Structure
:PROPERTIES:
:CUSTOM_ID: impl_structure
:END:


The current implementation is organised as a Rust workspace with two crates: the main {{{mark(bqti)}}} crate, containing the full protocol stack, and the {{{mark(bqti-ipc)}}} crate, a minimal Rust library project defining the shared types for interprocess communication between the daemon and CLI client {{{citep(bqti_impl)}}}. Separating both into separate projects avoids code duplication and reuse across contexts.

Inside the {{{mark(bqti)}}} crate, the remaining code is organised by four top-level modules. First, the {{{mark(bit\_torrent)}}} module contains the core protocol stack and metadata specification. It is responsible for the implementation and control of the stock protocol. Within it, the {{{mark(network)}}} module handles QUIC management, {{{mark(dht)}}} implements Kademlia peer discovery, {{{mark(session)}}} implements the peer wire protocol state machine, and {{{mark(chunks)}}} manages piece I/O operations.. The {{{mark(i2p)}}} module provides the simple SAM client implementation that proxies both {{{mark(bit\_torrent)}}} and {{{mark(network)}}} abstracting the core network management implementation. Finally, the {{{mark(ipc)}}} module that is responsible for managing the Unix socket control interface between the daemon and a client, in this case, the CLI client.
